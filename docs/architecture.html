↓
⚙ PodReconciler controller-runtime watch loop
Watches Pods and Kubernetes Events. Runs the full pipeline on each reconcile. Requeues every 30s for active incidents. Idempotent — safe to run multiple times on the same state.
↓
🔍 Incident Correlation
Deterministic GET by active name <workload>-<kind>-active. AlreadyExists race handled. One active incident per workload. Resolved incidents are preserved as historical records with a unique hash suffix.
↓
📦 Evidence Collection 6 collectors, bounded, best-effort
Trigger type determines which layers are collected. Failures in one layer don't block others. Collection has a 30s timeout.

Design principles

  • Read-only — no workload modifications
  • Deterministic naming — no duplicate incidents
  • Restart-safe — all state in CRD status (etcd)
  • Bounded — logs, events, API calls have limits
  • No LLM required — fully deterministic diagnosis
  • Honest uncertainty — Unknown is a valid outcome
  • Workload-aware recovery — replica counts, not raw Pods
  • 10 Prometheus metrics — operational observability
